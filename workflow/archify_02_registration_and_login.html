Deep-Dive: Security Implementation Details
■ Section A — Registration
STEP 1 Form Submission
User fills email, full_name (optional), and password (min 8 chars). handleSubmit() calls register() from AuthContext, which chains internally to authApi.register().
RegisterPage.tsx:26 → AuthContext.tsx:72–79 → api.ts:205–207
GUARD 409 Duplicate Email Check
Before creating a user, get_user_by_email() queries Postgres. If a row exists → HTTPException(409, "A user with this email already exists"). This prevents silent overwrites of existing accounts.
routes.py:33–38
CRYPTO get_password_hash() — bcrypt
Password is encoded to UTF-8 bytes, then hashed via bcrypt.gensalt(rounds=12) + bcrypt.hashpw(). 12 rounds = 2¹² = 4,096 bcrypt iterations. The salt is embedded in the output hash string — no separate column needed.
security.py:11–16
DB INSERT users + Auto-Login
User row inserted with is_active=True, is_superuser=False. After 201 response, AuthContext immediately calls login() to avoid a double-form UX — the user lands on dashboard already authenticated.
service.py:26–41 → AuthContext.tsx:74–78
■ Section B — Login
LOOKUP authenticate_user() — two-phase check
First fetches the user by email. If no row → return None → 401. If row exists, calls verify_password(). If hash mismatch → return None → 401. If is_active=False → return None → 401. Both failures surface the same generic 401 message to prevent user enumeration.
service.py:43–57
CRYPTO verify_password() — constant-time bcrypt
bcrypt.checkpw(password_bytes, hashed_bytes) is timing-safe: it always runs all 4,096 bcrypt rounds regardless of where a mismatch occurs, preventing timing-based user enumeration attacks.
security.py:19–26
JWT create_access_token() — HS256 signed JWT
Builds payload: {sub: user.email, iat: now, exp: now+ACCESS_TOKEN_EXPIRE_MINUTES, type: "access"}. Signs with SECRET_KEY using HS256 algorithm via PyJWT. The sub claim is later extracted in get_current_user() to identify the caller.
security.py:29–52
STORE tokenStorage.set() + authApi.getMe()
Token stored in localStorage["email_mon_auth_token"] via tokenStorage.set(). AuthContext then calls authApi.getMe() to fetch and hydrate the user profile — same flow as app initialization — setting user state and enabling isAuthenticated=true.
AuthContext.tsx:64–70 → api.ts:208–210
