▲ Flow A — Workspace Creation
AUTHget_current_user() — JWT validation only
POST /companies/ only requires a valid JWT. Any authenticated user can create a new workspace — no pre-existing company membership needed. The creator is automatically bootstrapped as OWNER.
create_company(current_user: User = Depends(get_current_user))
routes.py:36–40
ATOMICTwo-phase DB write in one transaction
db.flush() after INSERT companies forces Postgres to allocate company.id without committing, so CompanyUser FK can reference it. A single db.commit() then persists both rows atomically — crash mid-operation leaves zero orphan rows.
db.add(company); await db.flush() # allocate ID
db.add(membership) # role='OWNER'
await db.commit() # single atomic write
service.py:26–38
ROLEAutomatic OWNER assignment
The creator's user.id is hardcoded as owner_user_id. Role is set to CompanyRole.OWNER.value. The client cannot submit a role for this endpoint — no privilege escalation is possible at creation time.
membership = CompanyUser(company_id=company.id,
  user_id=owner_user_id,
  role=CompanyRole.OWNER.value)

▲ Flow B — Member Invite RBAC Layers
LAYER 1get_current_user() — JWT valid?
First layer: standard JWT validation. All 401 branches from auth/dependencies.py apply — expired token, malformed token, user not found. Identical to the /auth/me diagram.
auth/dependencies.py:15–64
LAYER 2get_company_membership() — Is caller a member?
Second layer: verifies the caller belongs to the target company. Returns 404 (not 403) even if the company exists but the caller isn't a member — this prevents membership enumeration (attacker can't distinguish "company doesn't exist" from "you're not a member").
if not company: raise 404 "Company not found"
if not membership: raise 404 "Company not found"
# Same message — no info disclosure
comp_dep.py:22–34
LAYER 3require_company_admin_or_owner() — Role ≥ ADMIN?
The RBAC gate. Checks membership.role not in [OWNER, ADMIN]. A MEMBER attempting to add colleagues hits a 403 Forbidden here. This prevents horizontal privilege escalation — a regular member cannot bootstrap their own teammates.
if membership.role not in [CompanyRole.OWNER.value,
                            CompanyRole.ADMIN.value]:
  raise HTTPException(403, "Owner or Administrator
    privileges required for this action")

The AddMemberModal role selector only exposes "MEMBER" and "ADMIN". The OWNER role is UI-blocked and schema-validated on the backend (Pydantic enum). No path for a non-OWNER to create another OWNER.
